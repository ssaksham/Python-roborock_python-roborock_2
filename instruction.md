We run discover_devices(prefer_cache=False) periodically so Home Assistant picks up account changes without a restart. New vacuums appear, but removed devices keep running and renamed devices and rooms retain their old details. Make a successful fresh discovery reconcile the manager with the current account, including devices shared with the user.

Devices that are no longer in the account must stop being returned and must release their subscriptions and reconnect work, even if discovery catches them while they are still connecting. Prune the cache so removed devices leave no stale per-device or network records behind, including leftovers from earlier runs, while preserving other devices' cached data. A valid empty account means all devices are gone. The pruned result must survive flushing and reopening a FileCache.

Reconciliation must be safe against work that is already in flight. Connections and refreshes belonging to a client that discovery has retired must not recreate or overwrite cache data afterwards, and if the same device later returns — or returns with changed details under a replacement client — the old client's delayed work must not clobber the newer client's state. Discovery itself may overlap with an earlier discovery or with cache writes from still-active devices; the manager must end up consistent with the latest successful account snapshot, without resurrecting removed devices, duplicating clients, or losing a live device's recent cache update. Cache implementations may hand out detached copies and suspend during get or set. Keep the existing Cache get/set interface and standalone DeviceCache behavior unchanged; this retirement behavior applies to manager-owned clients.

After reconciliation, a retained device's reported device and product details, including derived capabilities, must agree with a fresh construction from the same account data. Updating changed clients in place or replacing them is fine, but a device whose details have not changed must keep its live client and must not reconnect or emit another ready callback merely because discovery ran or another device changed.

Fresh account room names must reach retained V1 room traits without reconnecting otherwise unchanged devices or waiting for a new room identifier, and a newer account snapshot must always win over older room work that is still in flight. Keep room-name handling consistent with how a refresh already treats successful versus failed cloud lookups, preserve shared-device room lookup behavior, and preserve the existing suppression of repeated lookups for unresolved room identifiers.

A cache-preferred discovery or a failed cloud fetch falling back to cached data is not evidence of account changes: keep existing clients and cache entries intact, and cached data must still be usable to bootstrap a new manager when the cloud is unavailable. Preserve normal unsupported-device handling and the existing connection behavior for newly added devices.
