We run discover_devices(prefer_cache=False) periodically so Home Assistant picks up account changes without a restart. New vacuums appear, but removed devices keep running and renamed devices and rooms retain their old details. Make a successful fresh discovery reconcile the manager with the current account, including devices shared with the user.

Removed devices must stop being returned and release their subscriptions and reconnect work, including cancellation during connection startup. Remove their per-device cache entries and legacy DUID-keyed network records, along with orphaned entries left from an earlier run. A valid empty account means all devices are gone. Preserve other devices' cached data. The result must survive flushing and reopening a FileCache.

Late work owned by a retired client must not recreate its cached data. If the same DUID is later discovered again, the old client's delayed reads or writes must not overwrite the new client's cache. Cache implementations may return detached copies and suspend during get or set, so discovery must not replace a still-active device's recent cache update with an older snapshot. Keep the existing Cache get/set interface and standalone DeviceCache behavior unchanged; retirement applies to manager-owned clients.

A retained device's newly reported device and product details, including derived capabilities, must agree with a fresh construction from the same account data. Updating changed clients in place or replacing them is fine. Devices whose device/product details have not changed must retain their live client and must not reconnect or emit another ready callback merely because discovery ran or another device changed.

Fresh account room names must reach retained V1 room traits without reconnecting otherwise unchanged devices or waiting for a new room identifier. Their next room refresh must use the latest names and discard obsolete names. Preserve shared-device room lookup behavior and the existing suppression of repeated lookups for unresolved IDs. A successful empty room response clears obsolete names; a failed room lookup retains the last known names. An older room lookup finishing after rediscovery must not overwrite the newer account room names.

Because discovery runs periodically, it may overlap with itself or with device connection and refresh work already in progress. Overlapping fresh discoveries must settle on the latest account snapshot rather than resurrecting devices an overlapping call removed, and must not create duplicate clients or duplicate ready callbacks for the same device. The same late-work protections apply when a device's details change and its client is replaced: work started by the previous client must not overwrite the replacement client's cache or account state.

A cache-preferred discovery or a failed cloud fetch falling back to cached data is not evidence of account changes: keep existing clients and cache entries intact. Cached data must still be usable to bootstrap a new manager when the cloud is unavailable. Preserve normal unsupported-device handling and the existing connection behavior for newly added devices.
